# Telegram-бот-заглушка поискового сервиса

Заглушка воспроизводит диалог с внешним ботом без обращения к реальному сервису
и без использования персональных данных. Вместе с Telegram long polling она
запускает локальный HTTP-сервер тестовых TXT-отчётов.

Бот умеет:

- принимать `/inn <ИНН>`;
- возвращать найденный отчёт через URL-кнопку;
- отвечать «ничего не найдено»;
- намеренно не отвечать для проверки timeout;
- возвращать неизвестный формат ответа;
- отдавать пустой отчёт или отчёт без телефона;
- принимать `ФИО ДД.ММ.ГГГГ`;
- показывать страны через inline callback-кнопки;
- после выбора России вернуть отчёт, ответ без телефона или `not found`.

Все ФИО, телефоны, адреса почты и отчёты являются синтетическими.

## Подготовка

1. Создайте отдельного тестового бота через `@BotFather`.
2. Запишите токен в локальный `.env`:

```dotenv
TELEGRAM_BOT_TOKEN=токен-тестового-бота
```

Локальная раздача отчётов по умолчанию использует:

```dotenv
TELEGRAM_STUB_REPORT_HOST=127.0.0.1
TELEGRAM_STUB_REPORT_PORT=8081
TELEGRAM_STUB_REPORT_BASE_URL=http://127.0.0.1:8081
TELEGRAM_REPORT_ALLOWED_HOSTS=127.0.0.1:8081,localhost:8081
```

Первые три параметра имеют показанные значения по умолчанию. Переменную
`TELEGRAM_REPORT_ALLOWED_HOSTS` нужно задать явно: локальный HTTP-разрешается
только для точного сочетания адреса и порта. `BASE_URL` должен быть доступен
машине, на которой запускается тестовый пользовательский Telegram-клиент.

Установите зависимости:

```powershell
python -m pip install -r requirements.txt
```

## Запуск

```powershell
python -m src.integrations.telegram.stub_bot
```

Один процесс запускает и Telegram-бота, и HTTP-сервер отчётов. Остановить оба
компонента можно клавишами `Ctrl+C`.

## Сценарии поиска по ИНН

Сценарий определяется последней цифрой ИНН. Это делает тесты полностью
воспроизводимыми.

| Последняя цифра | Валидный тестовый ИНН | Ответ |
|---|---|---|
| `0` | `7700000030` | Отчёт с телефоном и почтой |
| `1` | `7700000111` | Отчёт без телефона; ФИО `Тестов...` запускает успешный второй поиск |
| `2` | `7700000062` | Явный ответ «ничего не найдено» |
| `3` | `7700000023` | Бот намеренно молчит для проверки timeout |
| `4` | `7700000094` | Неизвестный/неподдерживаемый формат ответа |
| `5` | `7700000055` | Отчёт без телефона; второй отчёт также без телефона |
| `6` | `7700000016` | Отчёт без телефона; второй поиск ничего не находит |
| `7` | `7700000087` | Кнопка отчёта есть, но TXT полностью пустой |
| `8`, `9` | `7700000048`, `7700000009` | Отчёт с телефоном и почтой |

Например:

```text
/inn 7700000030
```

вернёт отчёт с телефоном, а:

```text
/inn 7700000023
```

не получит ответа и должен завершиться по timeout основного клиента.

## Получение TXT

Как у имитируемого сервиса, URL кнопки заканчивается идентификатором отчёта:

```text
http://127.0.0.1:8081/r/with_phone/7700000030
```

Для получения текста основной клиент должен добавить `/txt`:

```text
http://127.0.0.1:8081/r/with_phone/7700000030/txt
```

URL можно открыть вручную, пока заглушка запущена.

## Второй поиск по ФИО и дате рождения

Отчёты без телефона возвращают одну из следующих синтетических пар:

```text
Тестов Тест Тестович 01.01.1990
Безномеров Борис Борисович 02.02.1990
Ненайденов Николай Николаевич 03.03.1990
```

После отправки такой строки бот показывает callback-кнопки стран.

- `Тестов...` + Россия → отчёт с телефоном;
- `Безномеров...` + Россия → отчёт без телефона;
- `Ненайденов...` + Россия → отредактированный ответ `not found`;
- любая страна кроме России → `not found`.

При отрицательном результате появляется кнопка `Попробовать комбинированный
поиск`. Она существует для проверки того, что основной сценарий её игнорирует.

## Интерактивный пользовательский клиент

Bot API не доставляет личные сообщения от одного бота другому, поэтому основной
сценарий проверяется отдельным тестовым пользовательским аккаунтом. В `.env`
нужны:

```dotenv
TELEGRAM_API_ID=12345678
TELEGRAM_API_HASH=секретный_api_hash
TELEGRAM_PHONE=+79990000000
TELEGRAM_TARGET_BOT=@username_тестового_бота
TELEGRAM_REPORT_ALLOWED_HOSTS=127.0.0.1:8081,localhost:8081
```

В первом терминале:

```powershell
python -m src.integrations.telegram.stub_bot
```

Во втором терминале:

```powershell
python -m src.cli.telegram_bot_console
```

При первом запуске Telegram запросит код авторизации. Локальный файл
`telegram_test_user.session` исключён из Git.

## Автоматические проверки

```powershell
python -m unittest discover -s tests -v
```

Модульные тесты не обращаются к Telegram или другим внешним сервисам. Они
проверяют выбор сценариев, структуру кнопок и содержимое обезличенных отчётов.
