# Памятка по запуску инструментов СБИС и Telegram

Развертывание, первый запуск, systemd, обновление и резервное копирование Linux-
сервера описаны в [`SERVER_OPERATIONS.md`](SERVER_OPERATIONS.md).

Команды выполняются в терминале из корня проекта:

```text
D:\GIT\INNtoPhone
```

Перед запуском заполните локальный `.env`:

```dotenv
SBIS_BROWSER_COOKIE=строка_cookie_из_браузерного_запроса
SBIS_RPC_URL=https://online.sbis.ru/service/
```

Cookie является секретом пользовательской сессии. Не добавляйте его в команды,
исходный код, документацию, Git или сообщения об ошибках.

## 1. Проверить список клиентов

Инструмент полностью получает CRM-список, но показывает только первые 10 строк с
ИНН и названием организации.

```powershell
python -m src.cli.sbis_clients_console 99788
```

Где `99788` — `ListId`. Посмотреть справку:

```powershell
python -m src.cli.sbis_clients_console --help
```

Основная функция инструмента возвращает полный список клиентов:

```python
from src.cli.sbis_clients_console import printClientsTable


clients = await printClientsTable(99788)
```

## 2. Получить контакты по ИНН

Инструмент получает карточку одного клиента и выводит найденные телефоны и email:

```powershell
python -m src.cli.sbis_contacts_console 500100732259
```

ИНН передается строкой из 10 или 12 цифр и проверяется по контрольным цифрам до
сетевого запроса. Посмотреть справку:

```powershell
python -m src.cli.sbis_contacts_console --help
```

Использование функции без консольного вывода:

```python
from src.integrations.sbis import getContactsByInn


contacts = await getContactsByInn("500100732259")
```

## 3. Обойти список и получить контакты

Корневой `main.py` объединяет первые два сценария:

1. Полностью получает список по `ListId`.
2. Для каждого клиента берет ИНН.
3. Получает контакты по ИНН.
4. Печатает одну строку: ИНН, организация, контакты.
5. Возвращает список найденных ИНН.

Запуск:

```powershell
python -m main 99788
```

Равнозначный прямой запуск:

```powershell
python main.py 99788
```

Посмотреть справку:

```powershell
python -m main --help
```

Использование из другого асинхронного модуля:

```python
from main import debugList


inns = await debugList(99788)
```

## 4. Обработать первые N клиентов через Telegram

Инструмент последовательно берет первые записи со статусами «В очереди на
обработку» и «Требуется повторная обработка». По умолчанию используется база
`data/clients.db`.

Для запуска нужны настройки тестового пользовательского аккаунта и имя бота в
локальном `.env`:

```dotenv
TELEGRAM_API_ID=
TELEGRAM_API_HASH=
TELEGRAM_PHONE=
TELEGRAM_TARGET_BOT=@username_бота
TELEGRAM_REPORT_ALLOWED_HOSTS=127.0.0.1:8081,localhost:8081
```

Для локального HTTP-сервера обязательно указываются точные адрес и порт:
`127.0.0.1:8081,localhost:8081`. Одной записи `localhost` без порта недостаточно.
Для реального бота разрешите только HTTPS-домен его отчетов, например:

```dotenv
TELEGRAM_REPORT_ALLOWED_HOSTS=*.sherlock-report.at
```

Запись без порта разрешает только стандартный HTTPS-порт `443`. Если реальный
сервис использует другой порт, укажите точный адрес, например
`reports.example.test:8443`; wildcard для нестандартного порта не применяется.
Переменная обязательна и не имеет значения по умолчанию. Без подходящего
allowlist загрузчик намеренно отклонит ссылку на отчет. Не добавляйте широкие
посторонние домены ради обхода этой проверки.

Сначала выполните dry-run для одной записи:

```powershell
python -m src.cli.telegram_enrichment --limit 1
```

Dry-run выполняет реальные запросы выбранному Telegram-боту и загружает отчеты,
но не записывает найденные контакты, статусы и попытки в SQLite.

После проверки результат можно сохранить:

```powershell
python -m src.cli.telegram_enrichment --limit 1 --write
```

Правила результата:

- найден телефон — `processed`;
- телефон не найден после обоих разрешённых поисков — `skipped`;
- timeout, FloodWait, HTTP 429 или временная ошибка — `retry_required`;
- неоднозначные ФИО/дата, некорректный ИНН или неизвестный формат —
  `needs_review`; такая запись больше не выбирается автоматически;
- email сохраняется, но сам по себе не завершает поиск как успешный.

В режиме `--write` клиент атомарно закрепляется перед запросом Telegram. Два
параллельных процесса не возьмут одну запись. Незавершённое закрепление после
аварийной остановки можно автоматически подобрать через 15 минут. Dry-run ничего
не закрепляет, поэтому не запускайте несколько dry-run одновременно на одной
очереди: они могут выполнить одинаковые внешние запросы.

Другой SQLite-файл и таймаут каждого действия Telegram задаются явно:

```powershell
python -m src.cli.telegram_enrichment --database .\data\clients.db --limit 5 --timeout 45
```

CLI выводит только агрегированные количества по статусам и кодам результата. ИНН,
названия организаций, телефоны и адреса почты в отчет не выводятся. Справка:

```powershell
python -m src.cli.telegram_enrichment --help
```

## 5. Запустить ежедневный конвейер

Единая команда сначала получает карточки организаций за предыдущий день и
записывает их в SQLite. Только после успешного завершения СБИС-этапа она открывает
Telegram, получает доступный баланс запросов и обрабатывает `queued` и
`retry_required`. Результаты Telegram всегда записываются в БД. После обработки
конвейер формирует отчет по организациям, зарегистрированным ровно 7 дней назад,
и отправляет его подписчикам отчетного бота:

```powershell
python -m src.cli.daily_pipeline
```

Значения по умолчанию:

- база: `data/clients.db`;
- дата: локальная вчерашняя дата компьютера;
- максимум очереди: `100` клиентов;
- таймаут действия Telegram: `45` секунд.

Параметры можно задать явно:

```powershell
python -m src.cli.daily_pipeline `
  --date 2026-08-09 `
  --database .\data\clients.db `
  --limit 1000 `
  --timeout 45
```

Если сбор СБИС завершился ошибкой, этап поискового Telegram-обогащения не
запускается, но независимые отчеты из уже сохраненной SQLite-БД все равно
отправляются. После этого команда завершается с исходной ошибкой. Если доступные
запросы закончились, текущий запуск прекращает платные запросы, а оставшаяся
очередь будет обработана в следующий день.

Для Планировщика заданий Windows:

1. Узнайте полный путь интерпретатора командой `Get-Command python`.
2. Создайте ежедневный триггер на нужное локальное время.
3. В поле «Программа» укажите полный путь к `python.exe`.
4. В аргументах укажите `-m src.cli.daily_pipeline --limit 1000 --timeout 45`.
5. В поле «Рабочая папка» укажите `D:\GIT\INNtoPhone`.
6. Для параллельного запуска выберите «Не запускать новый экземпляр».

Задание должно запускаться под тем же Windows-пользователем, которому доступны
локальные `.env` и Telegram-session. Эти файлы не следует копировать в Git.

## 6. Запустить бота отчетов

Создайте отдельного Telegram-бота и задайте настройки в `.env`:

```dotenv
TELEGRAM_REPORT_BOT_TOKEN=токен_отдельного_бота
REPORT_BOT_BOOTSTRAP_ADMIN_IDS=123456789
REPORT_LOW_QUERY_THRESHOLD=10
REPORT_RETENTION_DAYS=90
```

Запустите единственный long-polling процесс:

```powershell
python -m src.cli.report_bot --database .\data\clients.db
```

Bootstrap-администратор должен первым открыть личный чат с ботом и выполнить
`/start`. Бот не может первым начать диалог с пользователем. Запускать два
экземпляра polling с одним token нельзя.

Неизвестному пользователю бот показывает только его Telegram ID. После добавления
в whitelist пользователь выполняет `/subscribe`. Кнопка «Отчет по дате» открывает
месячный список дней с агрегатом `обработано/всего` и стрелками перехода между
месяцами. Выбранный отчет читается исключительно из SQLite: он не обращается к
СБИС и поисковому Telegram-боту и не расходует запросы. В Telegram отправляется
краткий список с первым телефоном и почтой, затем сразу прикладывается полный
XLSX с отдельными колонками контактов СБИС, карточки СБИС и Telegram. Команда
`/report YYYY-MM-DD` остается дополнительным прямым способом выбора даты.

Административные команды:

- `/add ID` и `/remove ID` — whitelist пользователей;
- `/admin_add ID` и `/admin_remove ID` — whitelist администраторов;
- `/admin` — inline-панель управления.
- `/report_status` — последний отчет и состояние его доставок.
- `/pipeline_status` — последний ежедневный запуск, его агрегаты и код ошибки.

Удаление пользователя, добавление администратора и удаление администратора
требуют отдельного inline-подтверждения, действующего 5 минут.

Отчеты с контактами доступны только в личных чатах и только пользователям из
whitelist. Повторный ежедневный запуск не отправляет уже доставленный отчет
повторно. Ошибка одного получателя не останавливает остальных.

## Отладка в VS Code

В `launch.json` для запуска модуля укажите:

```json
{
    "name": "СБИС: полный обход списка",
    "type": "debugpy",
    "request": "launch",
    "module": "main",
    "args": ["99788"],
    "cwd": "${workspaceFolder}",
    "console": "integratedTerminal",
    "justMyCode": true
}
```

Поставьте breakpoint слева от нужной строки и нажмите `F5`. Доступные аргументы
каждого инструмента всегда можно посмотреть через `--help`.

Для безопасной отладки Telegram-обогащения без записи в базу добавьте отдельную
конфигурацию:

```json
{
    "name": "Telegram: dry-run одного клиента",
    "type": "debugpy",
    "request": "launch",
    "module": "src.cli.telegram_enrichment",
    "args": ["--limit", "1", "--timeout", "10"],
    "cwd": "${workspaceFolder}",
    "console": "integratedTerminal",
    "justMyCode": true
}
```

Параметр `--write` в отладочную конфигурацию добавляйте только когда требуется
проверить сохранение результата в SQLite.
